# 中文文案規範

本專案所有中文文字的寫法，依據三份公開規範，各管一層：

| 層次 | 依據 |
| --- | --- |
| 標點符號 | 教育部《重訂標點符號手冊》 |
| 介面用語與語氣 | Microsoft 繁體中文（台灣）風格指南 |
| 中英混排與排版 | 中文文案排版指北（chinese-copywriting-guidelines） |

## 適用範圍

| 對象 | 範例 | 適用 |
| --- | --- | --- |
| 客服台介面 | 按鈕、標題、說明、提示、錯誤訊息 | 是 |
| 後端回傳的錯誤與系統訊息 | API `error`、對話中的系統訊息 | 是 |
| 傳給 LINE 使用者的訊息 | 歡迎詞、選擇確認、重複點選提示 | 是 |
| 工程端文字 | 缺口標題、`npm run reports` 輸出、程式註解、腳本輸出 | 是 |
| 文件 | README、CLAUDE.md、`docs/` | 是 |
| 示範內容 | `src/presets.ts`、`src/builder/presets.ts` 的範本內容 | 否 |
| 測試資料 | `test/` 中模擬使用者傳來的訊息 | 否（斷言系統輸出的文字仍須與程式一致） |
| 外部原文 | LINE API 回傳的錯誤、程式識別字、指令、路徑 | 否，保留原文 |

`npm run lint:copy`（`scripts/copy-lint.mjs`）會自動檢查下列可機械判斷的規則；語氣與措辭由撰寫者與審閱者負責。

## 一、排版（中文文案排版指北）

1. **中文與英文、數字之間加一個半形空格**：`LINE 官方帳號`、`最多 5 則`、`第 3 列`。
2. **數字與單位之間加空格**：`10 分鐘`、`300 字元`。百分比與度數例外：`50%`。
3. **全形標點與其他字元之間不加空格**：`請輸入「名稱」。`，不寫 `請輸入 「名稱」 。`。
4. **數字與英文字母一律半形**：`2026`，不寫 `２０２６`。
5. **專有名詞依官方大小寫**：LINE、CSV、JSON、Flex Message、Cloudflare、D1、R2、URL、API。
6. **插入變數**：變數為數字或代碼時兩側加空格（`第 ${n} 則`）；變數是名稱（客服人員、使用者、檔案）時以「」標示、不加空格（`由「${name}」負責`），中英文名稱都適用。

## 二、標點（教育部《重訂標點符號手冊》）

1. **中文語境一律使用全形標點**：`，。、；：？！「」『』（）`。英文整句、程式碼、網址、檔名內維持半形。
2. **引號用「」，引號內再引用用『』**，不用 `“ ”`、`" "`。
3. **刪節號為「……」**（兩個 `…`），只用於引文省略或語句未完，不用 `...` 或單一 `…`。列舉未完用「等」；進行中的狀態（`載入中`、`發送中`）比照狀態標籤，不加刪節號。
4. **頓號「、」用於並列的詞語**，逗號「，」用於分句。
5. **不重複標點**：不寫 `！！`、`？？`、`。。`。
6. **範圍**：句中以「至」表達（`1 至 5 則`）；表格、公式等空間受限處可用半形 `-`。不用 `～`、`~`。
7. **括號內為補充說明時用全形（）**；括號內全為英文或程式碼時，括號仍用全形：`（URI 編碼）`。

## 三、句末

1. **完整句子以句號結尾**：提示、說明、錯誤訊息、系統訊息、程式註解中的完整句。
2. **以下不加句號**：按鈕、標題、分頁與選單項目、欄位標籤、表格欄名、狀態標籤（`已發送`、`發送中`）、只有詞組的清單項目、placeholder。
3. **問句以問號結尾**，確認對話框的問題亦同。
4. **不用驚嘆號**。語氣靠措辭，不靠標點；問候語亦同（`感謝您加入好友。`）。
5. **一則提示含多句時**，每句皆以句號結尾。
6. **判斷是否為完整句子**：含兩個以上子句（中間有逗號）的提示視為完整句子，加句號；只有一個子句的狀態描述（`此訊息已被使用者撤回`、`下載中`）視為狀態標籤，不加句號。
7. **缺口標題**（`integrity_events.title`）視為標題，不加句號；需要多句說明時放進 `details`。處理說明（`resolution`）是完整句子，加句號。

## 四、用語與語氣（Microsoft 繁體中文風格指南、本專案慣例）

<!-- copy-lint-disable -->
1. **正式書面語**：不用口語（拿、塞、搞、看看、弄、OK）、不用表情符號與顏文字。
<!-- copy-lint-enable -->
2. **稱使用者為「您」**；系統自稱以主詞省略或「系統」為主，不用「我們」「小幫手」。
3. **量詞**：訊息用「則」，卡片用「張」，對話、檔案、項目用「個」，CSV 資料列用「列」，資料庫紀錄用「筆」。
4. **錯誤訊息說清楚兩件事**：發生了什麼、接下來怎麼做。先說結論：`無法發送訊息。請稍後再試。`
5. **動作用動詞開頭**：按鈕寫 `發送`、`重新發送`、`匯入`，不寫 `點此發送`。
6. **同一件事用同一個詞**：

   <!-- copy-lint-disable -->

   | 用 | 不用 |
   | --- | --- |
   | 發送 | 送出、傳送（指客服發訊時） |
   | 對話 | 聊天、會話 |
   | 客服人員 | 專員、小編 |
   | 使用者 | 用戶、客人、會員（指 LINE 端的人） |
   | 官方帳號 | OA、官帳 |
   | 互動訊息 | 按鈕訊息、選擇題（指可追蹤的 postback 訊息） |
   | 引用 | 回覆某則（指 quote） |
   | 撤回 | 收回、刪除（指 unsend） |
   | 接手／交還 | 認領、釋放 |
   <!-- copy-lint-enable -->

<!-- copy-lint-disable -->
7. **台灣用語**：檔案（非文件）、資料（非數據）、訊息（非信息）、預設（非默認）、設定（非設置）、支援（非支持）、網路（非網絡）、品質（非質量）。
<!-- copy-lint-enable -->
8. **程式註解**：同樣適用上述規則；技術識別字（`retry key`、`webhook`、`queue`）保留原文。
